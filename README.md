# Yoru — Windows-плеер для аниме

![Yoru 0.6.1 — библиотека с постерами аниме](docs/images/library.png)

[Выбор постера](docs/images/poster-picker.png) · [Ручные настройки](docs/images/settings-manual.png) · [Своя тема](docs/images/settings-custom.png)

Ранняя версия **0.6.1**. Есть русский дубляж, оригинал с вариантами субтитров, два встроенных плеера и страницы плееров сайтов. Автоматическое извлечение видеопотоков/переводов с сайтов не реализовано.

## Компактный плеер в 0.6.1

Под видео одна строка: озвучка, качество, перевод, параметры и следующая серия. Источник, выбор плеера, фильтр по типу субтитров и оформление находятся под шестерёнкой **«Параметры просмотра»**. Серии, персонажи и подсказка для демонстрации свёрнуты.

На контрольном снимке управление без видео занимает меньше 200 пикселей. Выбор языка оригинала убран из плеера, настроек и форм добавления: приоритет у японского, а для импортированных неяпонских источников язык берётся из их данных. Язык сохраняется при автоматической смене источника. Названия типов субтитров и сообщения русские; буквенные расширения нужны только при импорте файлов. Альтернативный плеер также использует русские подписи.

[Компактные параметры просмотра](docs/images/player-settings.png)

## Оригинал, разные переводы и AniDB в 0.6

В открытом аниме выбери **«Озвучка → Оригинал»** — японский выбирается по умолчанию. Через **«Параметры просмотра → Добавить источник или перевод»** добавь переводы от разных студий: у каждого своё название и текст. Поддерживаются UTF-8 файлы и ссылки SRT/VTT/ASS/SSA. Для SRT/VTT доступны размер и фон; ASS/SSA сохраняют авторское оформление. Можно менять формат и задержку добавленных дорожек без перезапуска видео.

Плееры **«Основной»** и **«Альтернативный»** переключаются с сохранением позиции, паузы, громкости, отключения звука и скорости. Автовосстановление сохраняет выбранный язык и точное качество. При добавлении источника можно выбрать страницу Yummyani / AnimeJoy: она открывается в отдельном изолированном окне приложения. Переводы и серии в этом окне управляются сайтом и пока не синхронизируются с нашим плеером.

![Оригинал и перевод с оформлением в Yoru 0.6.1 — тестовый видеофрагмент](docs/images/original-player.png)

Под сериями находится **«Персонажи и сэйю · AniDB»**: связь с ID каждого сезона, импорт XML, отдельное окно сайта и подключение собственного зарегистрированного HTTP-клиента AniDB. Общий состав сезона и ручные отметки текущей серии разделены. Полного автоматического каста каждой серии для всех аниме сейчас нет: если источник не дал такие сведения, приложение не подставляет весь сезон.

## Постеры аниме в 0.5

Вместо букв и разноцветных узоров — настоящие постеры. При добавлении нажми **«Постер → Выбрать»**, введи русское или английское название и выбери аниме и сезон из каталога AniLibria. Для существующей записи нажми **«Обложка»** под карточкой. Можно вставить свою HTTPS-ссылку или очистить поле, чтобы убрать постер. Выбор сохраняется вместе с библиотекой и не влияет на видео, качество или озвучку.

Поиск запускается кнопкой, возвращает до восьми вариантов и не выбирает первый результат автоматически. Повторный запрос хранится в памяти пять минут; изображения загружаются лениво и используют стандартный HTTP-кэш Electron. Ошибка изображения даёт нейтральную заглушку, без букв и бесконечных повторных запросов. Отказ каталога не останавливает просмотр. Для старой библиотеки постеры выбираются через «Обложка», без угадывания по названию.

Фон страницы и боковой панели теперь единый: при прокрутке и на длинных скриншотах нет резкой полосы. Все PNG в `docs/images` пересняты для 0.6.1; старые варианты удалены. На скриншоте — тестовая библиотека с реальными названиями и обложками, а не готовый каталог видеопотоков. При установке библиотека пустая. [Источник изображений и формат импорта](docs/posters.md).

## Новое имя и чистая боковая панель

Приложение теперь называется **Yoru** (夜, «ночь»). Нижние подписи про озвучку, версию и кнопку эффектов убраны из боковой панели. Озвучки и анимации настраиваются в отдельном разделе «Настройки». Старый каталог профиля `kadr-anime`, ключи хранилища и внутренний bridge сохранены ради совместимости с библиотекой и настройками. Исполняемый файл новой сборки — `Yoru.exe`. Перед первым запуском закрой прежнее приложение, если оно ещё открыто.

## Подробная настройка в 0.4

Открой **Настройки → Подробная настройка приложения**. Для собственного буфера выбери четвёртый режим **«Вручную»** — панель откроется автоматически. Готовые режимы остаются доступными и не стирают сохранённые ручные значения.

| Что настраивается | Доступные значения |
| --- | --- |
| HLS-буфер вперёд / назад | 5–90 с / 0–30 с; назад не больше, чем вперёд |
| Ориентир размера HLS-буфера | 8–128 МиБ; это не предел всей памяти процесса |
| Карточек в порции | 12 / 24 / 36 / 48 |
| Попыток на источник | 1–5, включая первую |
| Максимальное ожидание загрузки/зависания | 5–60 с; явная ошибка сервера обрабатывается раньше |
| Автосмена источника | Включена / выключена |
| Приоритет студий | AniDUB → AniLibria либо AniLibria → AniDUB |
| Другие русские студии | Разрешить / использовать только две основные |
| Начальная громкость | 0–100% |
| Скорость | 0.75× / 1× / 1.25× / 1.5× / 2× |
| Шаг перемотки стрелками | 5 / 10 / 15 / 30 с |
| Горячие клавиши приложения | Включены / выключены |
| Текст | 90–120% |
| Компактные карточки, блок продолжения и старт в «Кинозале» | Отдельные переключатели |

Буфер, число попыток, ожидание и выбор озвучек фиксируются при запуске серии: редактирование настроек не прерывает текущий просмотр. Громкость и скорость меняются сразу, не снимая видео с паузы. Ручная пауза не запускает восстановление. При зависании первой загрузки до получения метаданных тоже действует заданное ожидание.

Все варианты источников остаются строго русскими и с выбранным разрешением. Выключенная автосмена оставляет только первый подходящий источник и заданное число попыток. Сброс ручных параметров не удаляет библиотеку, историю, свою тему или выбранное разрешение. Старые настройки получают новые параметры по умолчанию.

Подробнее о проверке: [manual-settings-0.4.md](docs/manual-settings-0.4.md).

## Своя тема

![Редактор собственной темы](docs/images/settings-custom.png)

Открой **Настройки → Оформление → Своя**. Цвета фона, панелей, текста и акцента выбираются палитрой или вводятся HEX-кодом `#RRGGBB`. Ползунок меняет скругление интерфейса от 12 до 36 пикселей. Все изменения видны сразу и сохраняются после перезапуска.

Цвет текста основных кнопок выбирается автоматически для контраста; при низком контрасте обычного текста редактор показывает подсказку. Панель редактора сохраняет собственную читаемую палитру, чтобы можно было исправить неудачные цвета. Кнопка «Вернуть исходные цвета» сбрасывает только свою палитру и скругление, не затрагивая библиотеку, историю и режим просмотра.

Переход на любую готовую тему не удаляет свою: её можно снова выбрать позже. Четыре готовые темы сохранены.

## Темы и настройки в 0.3

Отдельный раздел «Настройки» содержит четыре полные палитры: «Тёплая ночь», «Север», «Сакура» и светлая «Молочная». Скруглены карточки, диалоги, панели и элементы управления; цвета применяются к библиотеке, настройкам и плееру. Сохранённая тема применяется до загрузки основного интерфейса.

[Светлая тема и настройки](docs/images/settings-cream.png) · [Тема «Сакура»](docs/images/settings-sakura.png)

Режимы влияют на реальные параметры приложения:

| Режим | Разрешение по умолчанию | Целевой HLS-буфер | Буфер назад | Лимит HLS по размеру | Карточек в порции | Эффекты |
| --- | --- | --- | --- | --- | --- | --- |
| Качество | 1080p | 30 с | 8 с | 40 МиБ | 24 | По настройке |
| Баланс | 720p | 20 с | 5 с | 24 МиБ | 24 | По настройке |
| Экономия | 480p | 12 с | 3 с | 12 МиБ | 12 | Отключены |

Это параметры HLS.js, а не жёсткие пределы всей памяти процесса: длительность сегментов и конкретный поток могут увеличивать фактический буфер. Для MP4 буферизацией управляет Chromium. Уменьшение буфера не гарантирует меньше остановок на нестабильном интернете. Источник должен предоставлять выбранное разрешение; программа сама качество не снижает.

Разрешение по умолчанию можно переопределить отдельно. Смена режима не перезапускает и не снимает с паузы текущую серию: новый буфер/разрешение используются при следующем запуске видео. Отдельно настраиваются анимации и автоматическая следующая серия. Системное уменьшение движения имеет приоритет над эффектами приложения.

Настройки хранятся в отдельном ключе `kadr.preferences.v1`, библиотека и история сохраняются. Профили 0.1/0.2 и прежняя настройка уменьшения анимаций читаются без сброса данных. Новые темы/режимы покрыты unit, браузерными и desktop-проверками. Настройка приватности GitHub не является функцией приложения и не меняется локальными настройками.

## Интерфейс и производительность

- Пять тем, векторные иконки и постеры с асинхронной загрузкой. Изображения не перекрашиваются темой приложения и не участвуют в логике воспроизведения.
- Блок продолжения последнего просмотра, сортировка и поиск по всей библиотеке; карточки выводятся порциями по 24 с кнопкой «Показать ещё».
- Кнопка «Кинозал» скрывает боковую панель и библиотеку. Escape возвращает обычный вид. F переключает полноэкранный режим, M — звук, пробел — паузу, стрелки — перемотку на 10 секунд. В полях ввода горячие клавиши не перехватываются.
- Короткие анимации появления и наведения без постоянно движущихся фонов и тяжёлого размытия. Системная настройка уменьшения движения и переключатель в настройках отключают эффекты.
- HLS-модуль загружается только при открытии HLS-видео. Основной JS версии 0.6: около 70 КБ (23 КБ gzip), плюс небольшой модуль загрузчика, при воспроизведении HLS дополнительно загружается модуль 575.28 КБ.
- Прогресс хранится отдельно от библиотеки: запись каждые 3 секунды больше не сериализует все серии и источники. Профиль версии 0.1 читается без потери избранного и истории.
- Зависимость HLS нужна только на этапе сборки и исключена из Node-зависимостей распространяемого приложения; собранный браузерный модуль остаётся внутри приложения.

Замеры в облачном Chromium и их ограничения: [performance.md](docs/performance.md). Они не подтверждают FPS, расход всей памяти Electron или работу на конкретном Windows-компьютере.

## Что реализовано

- Личная библиотека с поиском, избранным и историей на этом устройстве.
- Воспроизведение прямых HTTPS-ссылок MP4/WebM/HLS. Поддержка конкретного кодека зависит от Chromium/Electron.
- Сохранение позиции, ручной выбор серии и автоматический переход к следующей серии из импортированного списка.
- Приоритет источников: AniDUB → AniLibria/AniLiberty → другая русская озвучка. В режиме дубляжа автоматический выбор только при явной отметке `language: "ru"`; программа не распознаёт язык звука самостоятельно.
- По умолчанию две попытки на источник, затем следующий источник выбранных качества и языка; таймер зависания 15 секунд во время воспроизведения. Ручная пауза не вызывает переключение.
- Выбранное качество не снижается автоматически. Для HLS с мастер-плейлистом выбирается точное разрешение; для одиночного потока/MP4 качество берётся из данных источника.
- Ограниченный буфер HLS в памяти, без скачивания серий. Стандартный HTTP-кэш включён, в том числе для постеров; библиотека и прогресс сохраняются как метаданные. Офлайн-загрузка серий не реализована.
- Четыре сайта в разделе «Источники», также можно сохранить страницу плеера в библиотеке. Открываются в отдельных изолированных окнах без Node.js, доступа к файлам приложения и загрузок. Управление их внутренними плеерами пока не реализовано.

Нет гарантии непрерывности при недоступности сети и всех источников. Позиция переносится в секундах между указанными пользователем версиями одной серии; разные монтажи могут расходиться. Обновление истёкших ссылок и получение независимых резервных потоков потребуют адаптеров сайтов.

## Запуск и сборка

Нужен Node.js 24 (минимум 22.12 для инструментов сборки).

```sh
npm ci
npm test
npm run build
npm start
```

На Windows сборка папки приложения:

```sh
npm run package:win
```

Запускай `artifacts/Yoru-win32-x64/Yoru.exe`. Для переноса нужна **вся папка**, а не один EXE. Сборка не подписана; реальный запуск и захват звука Discord на Windows ещё не проверены.

Для ZIP-архива в среде с Python 3.11+: `python3 scripts/archive-win.py`. Скрипт проверяет целостность созданного архива и сохраняет рядом SHA256. Лицензия включённого в сборку HLS-плеера сохраняется в `LICENSE-hls.js.txt`.

В облачной Linux-среде для npm используй доступный каталог кэша: `npm --cache /workspace/.npm-cache ci`. Для кросс-сборки с унаследованным HTTP-прокси: `NODE_USE_ENV_PROXY=1 npm run package:win`. Загрузка Electron проверяет официальные контрольные суммы; не отключай TLS или проверки целостности.

`npm run dev` запускает интерфейс в браузере для разработки, а не Windows-приложение. Не рассчитывай на сохранение процесса сервера при восстановлении облачной среды.

## Список серий и резервных источников

Скопируй структуру из [playlist.example.json](docs/playlist.example.json), укажи свои прямые видеоссылки и импортируй файл кнопкой «Импорт списка». Домены `.invalid` в примере намеренно не работают. Повторяющиеся ID отклоняются без перезаписи существующих записей. Порядок серий в массиве задаёт порядок автоматического перехода. Для разного качества добавляются отдельные источники с `quality` 480/720/1080.

Данные библиотеки и ссылки хранятся локально в профиле приложения. Не публикуй файл со ссылками, содержащими личные токены.

## Проверки

```sh
npm test
npm run test:e2e
npm run test:desktop
```

Браузерные проверки используют установленный Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`) и FFmpeg для генерации короткого собственного тестового видео со звуком. Внешнее аниме не загружается. Они проверяют библиотеку, прогресс, отказы источников, языковой фильтр, качество и переход серии. Они не заменяют проверку на Windows.

`npm run test:desktop` запускает настоящий Electron с production-сборкой (`npm run build` перед тестом), отдельным временным профилем и собственным небольшим WebM-видео. Проверяет запуск через `file://`, preload, воспроизведение, сохранение библиотеки после перезагрузки, изоляцию окон источников и завершение приложения. На Linux нужен графический дисплей; в этой облачной среде проверка выполнена с виртуальным Xorg-дисплеем. Только для такого изолированного Linux-тестирования доступна переменная `KADR_ELECTRON_NO_SANDBOX=1`; обычное приложение и Windows-проверка не отключают sandbox.

GitHub Actions (`.github/workflows/windows.yml`) выполняет unit-тесты, настоящую desktop-проверку и сборку на `windows-latest`; ZIP сохраняется в артефактах успешного запуска. Наличие workflow не означает, что конкретный запуск уже прошёл: смотри его статус в разделе Actions.

Для Discord: в установленном клиенте выбери демонстрацию окна «Yoru» с передачей звука и проверь её со вторым участником. Для страниц источников выбирай соответствующее окно источника. При чёрном изображении можно проверить запуск с `--disable-gpu`. Программа не управляет настройками Discord и не обходит защиту видео.

## Что блокирует интеграцию сайтов

Первоначально запросы блокировал облачный прокси. После применения сетевых настроек повторная проверка 24 октября дала HTTP 403 для `g0e-1ka1v5q.troutcdn.site/283290` и HTTP 404 для `brogiro.cfd/series/283290/`. Причины этих ответов не установлены; они не доказывают недоступность сайтов с другого IP/VPN. Воспроизведение по этим страницам не подтверждено.
