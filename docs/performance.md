# Проверка интерфейса и оптимизаций 0.2

24 октября 2026 года. Сравнение исходной 0.1 и 0.2 в одной облачной Linux-среде, системный Chromium, production-сборка Vite, окно 1400×1000. Каждый вариант открыт в пяти новых браузерных контекстах. Данные синтетические: 500 аниме, по 5 серий и 3 источника на серию; воспроизведение во время замеров не включено. Видео с внешних сайтов не использовалось.

| Показатель | 0.1 | 0.2 |
| --- | ---: | ---: |
| Начальный JS, без сжатия | 589.19 КБ | 22.46 КБ |
| Начальный JS, gzip (по сборщику) | 184.82 КБ | 8.76 КБ |
| HLS JS, загружаемый отдельно по требованию | — | 575.28 КБ |
| DOM-узлы после начальной загрузки, медиана CDP | 8313 | 979 |
| Используемая JS-куча после принудительного GC, медиана | 3 992 802 байт | 2 820 268 байт |
| Время до наблюдаемой карточки после навигации, медиана | 269.5 мс | 234.5 мс |
| Поиск: действие Playwright → совпадающие карточки, медиана 25 запросов | 36.88 мс | 30.09 мс |

Статические размеры сборки и число узлов показывают конкретное уменьшение начальной работы. Времена включают задержки браузерной автоматизации и колебания общей облачной машины; пять повторов не дают оснований обещать такой же выигрыш на Windows. JS-куча не равна всей памяти Chromium/Electron. HLS-плеер при воспроизведении всё равно загружается полностью. Размер и базовый расход памяти самого Electron остаются существенными.

Исходные наблюдения текущего запуска сохранены в `artifacts/performance/before.json` и `after.json`. Повторить текущий вариант:

```sh
npm run build
npm exec vite preview -- --host 127.0.0.1 --port 4173 --strictPort
# В другом терминале из корня проекта:
node scripts/benchmark-ui.js after
```

Скрипт запускает отдельный headless Chromium. Путь к браузеру задаётся `CHROMIUM_PATH`; адрес production-сервера — `KADR_BENCHMARK_URL`. Для восстановления исходной 0.1 нужны её исходники/сборка; скрипт сам не откатывает проект и не создаёт worktree. Он записывает только собственный браузерный профиль с тестовыми данными и отчёт в `artifacts/performance`.

## Проверенное поведение

- Ленивая загрузка: во время открытия библиотеки и WebM-видео HLS-модуль не запрашивается.
- В библиотеке на 500 записей создаются 24 карточки. «Показать ещё» добавляет следующую порцию. Поиск охватывает все 500 записей.
- Избранное изменяется без пересоздания всей сетки в обычной библиотеке. Поисковые обновления объединяются через requestAnimationFrame.
- Прогресс записывается отдельно от большого JSON со всеми источниками. Старый формат 0.1 читается; тест проверяет, что при сохранении прогресса ключ библиотеки не перезаписывается.
- Воспроизведение WebM/HLS, русский язык, выбор качества, резервный источник, ручная пауза и следующая серия проверены на собственном FFmpeg-видео.
- Выход из плеера убирает video, снимает его обработчики, останавливает таймер восстановления и уничтожает HLS-экземпляр. Повторное открытие окон источников больше не добавляет обработчик загрузок к одной сессии каждый раз.
- «Кинозал», пауза/звук с клавиатуры, системное уменьшение движения и сохранение настройки эффектов проверены в браузере. Скриншоты проверены при ширине 1400 и 960 пикселей; горизонтального переполнения на минимальном размере окна нет.

## Ограничения

Прогона Windows-приложения, длинного теста утечек, измерения FPS и проверки Discord на Windows не было. Результаты не подтверждают стабильность внешних сайтов: их адаптеры ещё не реализованы. Никакие проверки доступности сайтов не заменялись тестовыми успешными ответами; синтетические media-fixtures используются только для локальных проверок плеера.
