# Источники для Windows-приложения

Проверено 24 октября 2026 года. Это результаты исследования, а не готовая интеграция или подтверждение воспроизведения.

## Подтверждённые материалы

### AniLibria / AniLiberty

- [Официальная организация](https://github.com/anilibria).
- [Документация прежних API](https://github.com/anilibria/docs): README прямо объявляет их выведенными из эксплуатации и указывает актуальную документацию: <https://anilibria.top/api/docs/v1>.
- [Официальный мобильный клиент](https://github.com/anilibria/anilibria-app) называет проект AniLiberty (ex AniLibria) и ссылается на <https://aniliberty.top/>. Для исследования прочитан commit `a188bfd5e49fd5afee5ff3ec253db92176eaf532`.
- [Клиент Windows/macOS/Linux](https://github.com/anilibria/anilibria-winmaclinux) описывает использование libmpv. Страница последнего релиза при проверке перенаправила на [2.2.36 stable](https://github.com/anilibria/anilibria-winmaclinux/releases/tag/2.2.36).

Это обоснованный кандидат для первого адаптера AniLibria. Наличие других студий, резервных независимых потоков, доступность видео через VPN и отсутствие требований авторизации пока не подтверждены. Код мобильного клиента использует свой API; его нельзя без проверки выдавать за контракт нового публичного API.

### Kodik — кандидат для исследования нескольких озвучек

- [Поиск репозиториев](https://github.com/search?q=Kodik+API&type=repositories).
- [Сторонний Rust-клиент](https://github.com/negezor/kodik-api-rust) показывает поля `translation`, `kinopoisk_id`, `shikimori_id`, сезоны и серии. Пример требует API-ключ.

Это сторонняя документация, не подтверждение доступности сервиса или разрешённого подключения нашего приложения. AniDUB в актуальном каталоге, выдача прямых потоков и управление внешним плеером не проверены. Чужие ключи из примеров не использовались. Адаптер не подключён; новый секрет пока не запрашивается.

### AniDUB

- [Поиск репозиториев](https://github.com/search?q=AniDUB&type=repositories).

Это не подтверждённый актуальный API и не подходит как готовое решение: пользователь выбрал потоковый просмотр без скачивания серий. Официальный работающий API для требуемых функций пока не установлен.

### Изменённые ссылки Кинопоиска

Пользователь уточнил сервис: на странице конкретного аниме заменяет домен `kinopoisk.ru` на `kinopoisk.cx`, сохраняя путь страницы. Если в адресе есть `www`, его сохраняет та же замена. Это описание пользователя, а не подтверждённая интеграция.

24 октября проверены запросы к `https://www.kinopoisk.cx/film/370/`, `https://www.kinopoisk.cx/series/749374/` и `https://kinopoisk.cx/film/370/`. Все три отклонены облачным прокси на этапе CONNECT с `403 Forbidden`; HTML сайта не получен. В черновик добавлены `kinopoisk.cx` и `www.kinopoisk.cx`, предыдущие разрешённые домены сохранены.

Пути `/film/<id>/` и `/series/<id>/` нужно проверять отдельно после применения сетевых настроек. Существование этих маршрутов на `.cx`, перенаправления, список плееров, доступные озвучки, сезоны, серии и управление воспроизведением пока не установлены. Совпадение пути не доказывает связь с официальным Кинопоиском или наличие API. До проверки не включать сайт в список работающих источников.

Дополнительно проверены `https://g0e-1ka1v5q.troutcdn.site/283290` и `https://brogiro.cfd/series/283290/`. Параметр `utm_source` у второй ссылки исключён из запроса как метка перехода; путь и идентификатор сохранены. Оба запроса отклонены облачным прокси на этапе CONNECT с `403 Forbidden`, HTML не получен. В черновик добавлены именно `g0e-1ka1v5q.troutcdn.site` и `brogiro.cfd`, без wildcard. Нельзя утверждать, что первый URL — прямой поток/CDN или что два сайта используют независимые источники: это не установлено по содержимому страниц.

Повторная проверка перед отправкой на GitHub, 24 октября: текущая политика уже `enforced`, оба домена включены. На этот раз получены HTML-ответы HTTP 403 от первого адреса (title `www`) и HTTP 404 от второго (title `Flicksbar`). Это уже не прежний отказ CONNECT. Причина HTTP-ответов, возможность просмотра с пользовательским VPN и доступность плееров пока не установлены; функциональная интеграция не подтверждена.

GitHub и raw.githubusercontent.com отвечали HTTP 200 для указанных выше доступных материалов. Прямые запросы к Google, AniLiberty, AniDUB и Кинопоиску отклонены облачным HTTP-прокси на этапе CONNECT: `403 Forbidden`. Это ограничение окружения, а не доказательство недоступности сайтов.

Существующий preset пакетных менеджеров сохранён. Сохранение черновика само по себе не применяет политику и не публикует окружение. После применения настроек нужно проверить актуальную документацию API, поиск, список серий, озвучки, манифест и небольшой сегмент потока. Выявленные домены CDN следует добавлять отдельно после проверки, а не разрешать весь интернет.

## Согласованное поведение приложения

- Windows 10/11, отдельное окно; поиск, каталог, избранное, история.
- Приоритет AniDUB → AniLibria/AniLiberty → другая подтверждённая русская озвучка. Не выбирать неизвестный язык, субтитры или иностранную дорожку как автоматическую замену.
- Сначала повторить загрузку и обновить истёкшую ссылку, затем искать другой источник той же серии с той же озвучкой. Если её нет, допускается следующая русская озвучка по приоритету с заметным уведомлением.
- Идентифицировать сезон и серию; сверять версию и тайминг. Нельзя слепо переносить секунды между разными монтажами или принимать другой URL того же CDN за независимый резерв.
- Сохранять выбранное качество. Не понижать его автоматически ради непрерывности. При полном отказе источников или сети пауза неизбежна.
- Автоматическая следующая серия. Готовить её метаданные и ссылку заранее; только ограниченный буфер в памяти, без сохранения серий и без торрентов.
- Восстановление ограничено по числу попыток и времени; ручная пауза и смена серии отменяют старые попытки. Предусмотреть понятное сообщение при исчерпании источников.
- Для Discord: одно стабильное окно и вывод звука плеера в обычное аудиоустройство. Проверять захват окна и звука в установленном Discord на Windows; облачный Linux такую проверку не заменяет. Не обещать обход DRM или гарантированную работу демонстрации для всех источников.

## Что ещё не проверено

В репозитории реализована ранняя версия приложения для прямых видеоссылок и импортируемых списков серий. Это не готовая интеграция перечисленных сайтов. Каталоги внешних сервисов, доступность AniDUB на них, независимые резервные потоки, обновление истёкших ссылок, точность позиции между разными монтажами и звук Discord на Windows ещё требуют проверки. Автотесты используют собственное синтетическое видео; их результат не подтверждает воспроизведение с пользовательских сайтов.
